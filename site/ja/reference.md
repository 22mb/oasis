# CLI と API

## CLI {#cli}

```
oasis-gen <SPEC> [-o <FILE>] [--lang <LANG>]
```

| 引数 | 意味 |
| --- | --- |
| `SPEC` | OpenAPI ドキュメントの JSON か YAML のファイル、または標準入力を表す `-` |
| `-o`、`--output FILE` | 標準出力の代わりに `FILE` へ書き出し |
| `-l`、`--lang LANG` | 生成対象の言語。現在は `typescript`（既定値）のみ |
| `-h`、`--help` | ヘルプの表示 |
| `-V`、`--version` | バージョンの表示 |

- oasis-gen は、ほかのローカルファイルへの `$ref` をたどります。参照先は、参照元のドキュメントからの相対パスとして解決されます。ドキュメントを標準入力から読み込んだときは、カレントディレクトリーからの相対パスとして解決されます。
- ドキュメントが不正であるなどのエラーが発生すると、oasis-gen は標準エラー出力に `error: ...` を出力し、終了ステータス 1 で終了します。
- 出力は `Generated by oasis-gen ... Do not edit.` という行で始まります。

## 動作要件 {#requirements}

- **Node.js** 24 以降が、CLI と生成されるクライアントの両方に必要です。クライアントは、ブラウザー、Deno、Bun でも動作します。
- **TypeScript** 5.0 以降が必要です。生成されるファイルには、`lib` の ES2022 以降が必要です。さらに `fetch`、`Request`、`Response` の型のために、`lib` の `dom` か `@types/node` のどちらかが必要です。
- 生成されるファイルは TypeScript の消去可能な構文（erasable syntax）だけを使っているため、Node.js の Type Stripping でもそのまま実行できます。

このサイトのコード例は `./api.ts` をインポートしています。このインポートには、`allowImportingTsExtensions`（Vite のテンプレートでは設定済み）か Node.js の Type Stripping が必要です。どちらも使わないときは、モジュール解決の方式に合わせて `./api.js` か `./api` をインポートしてください。

## インストール {#installation}

npm パッケージには、macOS（arm64、x64）、Linux（arm64、x64）、Windows（arm64、x64）向けのビルド済みバイナリーが含まれています。Linux 向けのバイナリーは静的リンクされているため、glibc と musl のどちらの環境でも動作します。npm は、お使いのプラットフォーム向けのバイナリーだけをインストールします。GitHub の各リリースにもアーカイブが添付されています。代わりにソースからビルドするときは、次のコマンドを実行してください。

```sh
cargo install --git https://github.com/22mb/oasis
```

## API {#api}

生成されるファイルは、次のものをエクスポートします。

| エクスポート | 説明 |
| --- | --- |
| `createClient(options?)` | クライアントを作成する関数。[操作の呼び出し](./client)を参照 |
| `auth(credentials)` | ドキュメントの `security` の指定どおりに資格情報を送信するミドルウェア。[認証](./authentication)を参照 |
| `DecodeError` | 本体が `Content-Type` と一致しないときに投げられるエラー。[エラー](./client#decodeerror)を参照 |
| `Pet` や `AccountRequest` などのスキーマの型と、`Kind` などの列挙値 | [スキーマ](./schemas)を参照 |
| `paths` | すべての操作の入力とレスポンス（パスとメソッドごと） |
| `schemas`、`components` | ドキュメントのスキーマ（名前ごと）。[スキーマ](./schemas#type-aliases-and-components)を参照 |
| `ApiResponse<Responses>` | 呼び出しの結果の型（操作の `responses` から作成） |
| `Client<Paths>`、`ClientOptions`、`RequestOptions` | クライアント、そのオプション、呼び出しごとの fetch オプション |
| `Middleware`、`MiddlewareContext`、`OperationInfo` | ミドルウェアと、ミドルウェアが受け取る情報。[ミドルウェア](./middleware)を参照 |
| `Credential`、`SecurityRequirement`、`SecuritySchemeName` | `auth` が使う型 |
| `ServerSentEvent` | `text/event-stream` のレスポンスの 1 項目（`{ data, event?, id?, retry? }`） |

### `ClientOptions` {#clientoptions}

| オプション | 型 | 説明 |
| --- | --- | --- |
| `baseUrl` | `string` | ドキュメントのすべてのサーバーを置き換えるベース URL |
| `headers` | `HeadersInit`、またはそれを返す関数（非同期も可） | すべてのリクエストで送信するヘッダー |
| `middleware` | `Middleware[]` | すべてのリクエストをラップするミドルウェア（先頭が最も外側） |
| `fetch` | `(request: Request) => Promise<Response>` | グローバルな `fetch` の代わりに呼び出す関数 |

### `Middleware` {#middleware}

```ts
type Middleware = (
  request: Request,
  next: (request: Request) => Promise<Response>,
  context: { operation: OperationInfo },
) => Promise<Response>;
```

| `OperationInfo` のフィールド | 型 | 内容 |
| --- | --- | --- |
| `method` | `string` | 呼び出しで使われたとおりの HTTP メソッド |
| `path` | `string` | `/pets/{petId}` などのパステンプレート |
| `operationId` | `string`（省略可能） | `operationId`（ドキュメントに記述があるとき） |
| `security` | `SecurityRequirement[]` | 適用されるセキュリティ要件（ドキュメントでの記述順） |

### `Credential` {#credential}

```ts
type Credential =
  | string
  | ((
      scopes: string[],
      context: MiddlewareContext,
    ) => string | undefined | Promise<string | undefined>);
```

`undefined` または `""` は、その資格情報が利用できないことを表します。

### 結果の型付け {#typing-results}

`ApiResponse` には、`paths` から取り出した操作の `responses` を渡します。

```ts twoslash
import type { ApiResponse, paths } from "./api.ts";

type GetPet = ApiResponse<paths["/pets/{petId}"]["GET"]["responses"]>;
```
